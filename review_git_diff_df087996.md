## Git Diff Review

**0 critical, 12 warnings, 8 suggestions**

🟡 **12 Warnings**

- `Engine/Source/Event/EvtSched.cpp:597` - `SpikeLogTickStart()` calls `SpikeLogCheckEnv()` on every tick, so an unset/failed `WOWLOG_SPIKES` re-runs `getenv()` once per frame. The original checked once at first tick inside `SpikeLogInit`. Cheap but avoidable given the module's own claim that an off logger costs one branch per call site.
- `Engine/Source/Event/EvtSched.cpp:581` - `atol(value)` with no range check: a huge or negative `WOWLOG_SPIKES` value truncates into `uint32_t` (e.g. 5000000000 -> wraps), unlike `CCommand_Perf` which rejects values > 0xFFFF. A wrapped threshold silently means "never log a spike" — the exact failure mode the console path guards against. Reuse the same validation.
- `Engine/Source/Event/EvtSched.cpp:656` - Duplicate/near-duplicate `OsGetAsyncTimeMs()` calls per tick: `currTime` (line 652), then `tickStart` (656) which is really the same instant, plus one per `PerfLogStage` (10 per frame) and one in `PerfLogTickEnd`. With the logger off, `PerfLogStage` early-returns before reading the clock, so tickStart could just be `currTime` — the two reads differ by an unmeasured tick and make the frame/work split slightly inconsistent with the engine's own phase timing.
- `Engine/Source/Event/PerfLog.cpp:311` - `PerfLogEnabled()` / `PerfLogThreshold()` / `PerfLogOpenFailed()` read non-atomic globals written under `s_lock` (and `s_enabled` is written by `PerfLogSetThreshold` from the console thread). Reading them without the lock is a data race in the formal sense; more concretely, `CGxDeviceD3d::ScenePresent` now branches on `PerfLogEnabled()` so a torn/stale read changes the measured path. Make these `std::atomic<bool>`/`volatile` or take the lock.
- `Engine/Source/Event/PerfLog.cpp:243` - `WriteSpikeLine` uses `s_lastTickStart - s_startMs` for the elapsed column, but `PerfLogTickEnd` updates `s_lastTickStart = tickStart` *after* calling `WriteSpikeLine`, so the first spike after `PerfLogSetThreshold` prints `0 ms` (s_lastTickStart was set to now by SetThreshold). Cosmetic but misleading in exactly the first line anyone reads.
- `Engine/Source/Event/PerfLog.cpp:508` - `workMs = now - tickStart` is computed before `CloseStageLocked(now)`, which also does a file write (`WriteSpikeLine`) later in the same call. The work figure therefore excludes the logger's own `fprintf`/`fopen` cost in the spike path — acceptable, but the "work" number is now systematically low on exactly the frames being investigated, and nothing in the comment says so.
- `Engine/Source/Event/PerfLog.cpp:437` - `PerfLogSpanDetail` drops spans under 5 ms from the per-frame list *after* adding them to the window totals; the window `SpanTotal` list has capacity `kMaxCounters * 2` (24) while texture/async/GC spans can exceed that, and `NoteSpanInWindow` silently discards anything beyond capacity — including a long `async-wait` if 24 other names registered first in the window. The window summary can therefore miss the span that mattered.
- `Engine/Source/Gx/CGxDeviceD3d/CGxDeviceD3d.cpp:3267` - The `PerfLogEnabled()` branch duplicates the whole `WaitForFPSCap()` + `Present()` + error-handling block in both `CGxDeviceD3d` and `CGxDeviceD3d9Ex`. Any future change to the present path (e.g. the `m_context = 0` failure handling) must be made twice and can silently diverge. Prefer timing unconditionally with the clock reads folded into `PerfLogSpan`'s own gate, or a tiny RAII scope timer.
- `Engine/Source/Model2/M2Cache.cpp:204` - `PerfLogCount`/`PerfLogSpan` are called from `CM2Cache::GarbageCollect`, which `PerfLog.h` itself says runs on worker threads, but these are per-*frame* counters (`s_counters`/`s_spans` reset at `PerfLogTickStart`). A worker-thread GC therefore reports into whichever frame happens to be open — its spans can be attributed to an unrelated frame's spike line, and the count can be wiped by a concurrent TickStart. The header acknowledges thread-safety of the data but not this attribution hazard; either route worker spans to the window only, or document it.
- `Engine/Source/ModernAssets/Dbc/DbcMerge.cpp:209` - The added guard reads `StringFieldTable().count(tableName)` to decide whether a table is known, but `StringFields()` (line ~104) already returns `kNone` for unknown tables — the two lookups are duplicated, and the guard is placed *after* `ParseDbc` and `StringFields`, so a missing map still parses the base table first. More importantly, a known table with an empty entry (e.g. `"Item" -> { }`, line 106 of DbcStringFields.h) passes the guard and then silently copies string offsets through unre-based — the exact garbage-tooltip bug the header warns about. `Item` having no string fields is suspicious given the file's own rationale; verify the generator's output for `Item`.
- `Engine/Source/ModernAssets/Dbc/DbcMerge.cpp:212` - Typo introduced in the moved doc comment: "that file'" (missing closing `s`) and "an unre-based offset" — the latter is a typo for "un-rebased". Also the block was demoted from `/** */` to `///`, which changes Doxygen rendering if the project extracts these.
- `Engine/Source/ModernAssets/Dbc/DbcMerge.cpp:41` - `HeaderValid` checks `total <= size` but not `total` overflow of `sizeof(WdbcHeader) + records + h.stringBlockSize` (records is 64-bit and capped, stringBlockSize is 32-bit, so total fits in 64-bit — OK), yet `ParseDbc` then does `h.recordCount * h.recordSize` in 32-bit to compute `recordsBytes`, which can overflow differently from the 64-bit check when recordCount*recordSize exceeds 2^32 (HeaderValid only caps records at 0xFFFFFFFF). A crafted DBC can pass validation and then under-size `recordsBytes`, making the string block slice read past the buffer.

🔵 **8 Suggestions**

- `Engine/Source/Event/EvtSched.cpp:660` - `PerfLogStage("SynthesizeInitialize")` is called unconditionally at the tick boundary, but the surrounding phase markers are also named after functions that may be skipped (`IEvtInputProcess` is still staged before its `m_schedFlags & 2` guard is checked, so a skipped phase shows as 0 ms rather than being absent). Consistent enough, but the new comment implies a deliberate boundary stage that reads oddly beside the `"frame-end"` marker.
- `Engine/Source/Event/PerfLog.cpp:183` - `Percentile()` returns `1024` when the target exceeds the histogram total (empty bucket walk), which prints as "p99=1024" in the summary instead of being clamped to 1023; the comment acknowledges the overflow bucket but the return value is outside the bucket range.
- `Engine/Source/Event/PerfLog.cpp:196` - `NoteSpanInWindow` matches on `SameName` against a 32-char truncated copy, so two distinct span names sharing the same first 32 characters would merge. Fine today, but `CopyName` truncation is silent — a longer name loses its tail with no warning.
- `Engine/Source/Event/PerfLog.cpp:352` - `PerfLogSetThreshold` calls `WriteHeader` before `ResetWindow`, and on re-enable writes an append header each time, so a file toggled on/off repeatedly accumulates header lines with no run separator. Minor; also `s_openFailed` is never cleared, so a transient failure permanently reports "WRITE FAILED" until restart.
- `Engine/Source/Gx/CGxDeviceD3d/CGxDeviceD3d.cpp:3267` - The comment says this is "gated on the logger being on" to avoid perturbing Present, but `OsGetAsyncTimeMs()` is called 2-4 extra times per present when enabled — the measurement still lands inside the frame being measured. `PerfLogSpan` already early-returns when disabled, so the gate saves only the clock reads, not the branch; consider timing unconditionally for simpler code, or state the tradeoff honestly.
- `Engine/Source/Model2/M2Cache.cpp:180` - `const uint32_t start = now;` shadows nothing but then `now` is unused for anything except the span (the loop body does not use it). Verify the original `now` is still needed; if not, fold to a single `const uint32_t start = OsGetAsyncTimeMs();`.
- `Engine/Source/ModernAssets/Dbc/DbcMerge.cpp:34` - Pre-existing, touched region: `static_assert(sizeof(WdbcHeader) == 20);` appears twice back to back. Harmless, but adjacent to the change and clearly a copy-paste slip worth removing.
- `Engine/Source/ModernAssets/Dbc/DbcMerge.cpp:272` - `idToIndex` reserves `merged.header.recordCount + cont.header.recordCount` but is rebuilt per continuation inside the loop, and `merged.header.recordCount` is only updated at the end of each continuation — correct, but the reserve on the first iteration uses the pre-merge count and under-reserves on later tiers. Minor.

**Summary:** The instrumentation refactor is well-commented and mostly sound, but it introduces several correctness gaps: unsynchronized reads of the logger's enable flag (which the new Present-path branch depends on), an unchecked `atol` -> uint32 threshold that can wrap and silently disable spike logging, worker-thread GC spans/counters being attributed to whichever frame is open, and a silent capacity cap in the window span totals. The DbcMerge change adds a useful guard but leaves an inconsistency where a table with an empty string-field list (notably `Item`) passes validation and copies offsets through unre-based — the exact bug the accompanying comment describes — and `ParseDbc`'s 32-bit `recordCount * recordSize` can still overflow past the 64-bit `HeaderValid` check.
